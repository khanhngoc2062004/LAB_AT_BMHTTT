# MIDTERM PROJECT REPORT

## 1. Research Paper

Title: Software security in practice: knowledge and motivation

DOI: 10.1093/cybsec/tyaf005

## 2. Project Objective

Study and demonstrate the qualitative analysis
workflow used to investigate developers'
security knowledge and motivation.

## 3. Research Method

The demo follows these analysis stages:

1. Open Coding
2. Axial Coding
3. Selective Coding
4. Knowledge Acquisition Classification
5. Motivation and Barrier Analysis

## 4. Implementation

Environment: Ubuntu 24.04 WSL2

Tools: Bash, CSV, Markdown, awk

Dataset: 8 synthetic interview statements

Coding method: Manual qualitative coding

Validation: Bash scripts

## 5. Results

Interview statements: 8

Open codes: 8

Axial categories: 3

Core categories: 1

Knowledge learning types: 3

Motivation and barrier categories: 4

The Bash demo successfully summarizes the
coded data and checks selected ID constraints.

## 6. Limitations

The original interview transcripts were
not used in this demonstration.

The dataset contains synthetic examples.

Coding decisions were made manually.

The analysis does not reproduce the original
paper's empirical findings.

## 7. Future Work

1. Study the original coding framework in detail.
2. Design a larger interview dataset.
3. Document coding rules and decisions.
4. Evaluate agreement between independent coders.
5. Improve data validation and reproducibility.
6. Compare results with the original paper
   where sufficient methodological details exist.

## 8. Conclusion

The midterm project demonstrates a simplified
qualitative coding workflow.

The current implementation is suitable for
explaining the analysis process but is not
an independent empirical replication.
